POC 1 — ConfigMap: Volume Mount + Env Var Reference

1. Create ConfigMap `app-config` with keys: `APP_ENV=production`, `APP_NAME=inventory-service`.
2. Create pod `config-inspector` (`toolbox` image), that:
   - mounts `app-config` as a volume at `/etc/app/config`
   - also injects `APP_ENV` as an environment variable via `configMapKeyRef`
3. Verify:
   - `kubectl exec config-inspector -- cat /etc/app/config/APP_ENV`
   - `kubectl exec config-inspector -- printenv APP_ENV`


#configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  APP_ENV: production
  APP_NAME: inventory-service

  
#app-config-inspector.yaml
apiVersion: v1
kind: Pod
metadata:
  name: config-inspector
spec:
  containers:
    - name: toolbox
      image: qamre/toolbox:v1
      env:
        - name: APP_ENV
          valueFrom:
            configMapKeyRef:
              name: app-config
              key: APP_ENV
      volumeMounts:
        - name: app-config
          mountPath: /etc/app/config
  volumes:
    - name: app-config
      configMap:
        name: app-config

POC 3 — Secret: Volume Mount + Env Var Reference
Create Secret db-credentials with keys username and password.
Create pod secret-inspector (toolbox image), that:
mounts db-credentials as a volume at /etc/app/secrets
injects username as env var DB_USERNAME via secretKeyRef

Verify:
kubectl exec secret-inspector -- cat /etc/app/secrets/DB_USERNAME
kubectl exec secret-inspector -- cat /etc/app/secrets/DB_PASSWORD
kubectl exec secret-inspector -- printenv DB_USERNAME
kubectl exec secret-inspector -- ls -l /etc/app/secrets

Expected result: Both username and password appear as files under /etc/app/secrets with their decoded (plaintext) values. 
printenv DB_USERNAME returns the username value. ls -l shows the Secret volume mounted with restrictive file permissions (0644 by default, root-owned) and backed by tmpfs rather than disk.

Solution:-

secret.yaml
apiVersion: v1
kind: Secret
metadata:
  name: db-credentials
#opaque is the generic type of secret for the (coredentilas)
type: Opaque  
stringData:
  DB_USERNAME: admin
  DB_PASSWORD: admin123

#pod-secret-inspector.yaml

      volumeMounts:

POC 7 — PV + PVC: Persistence Across Pod Recreation
Create a 1Gi PersistentVolume (hostPath is fine for a local cluster).
Create a PVC that binds to it.
Create pod pvc-test (toolbox image), mounting the PVC at /data.

kubectl exec pvc-test -- sh -c 'echo hello-from-poc7 > /data/hello.txt'
Delete pod pvc-test. Recreate it with the same PVC.
kubectl exec pvc-test -- cat /data/hello.txt

Expected result: /data/hello.txt still contains hello-from-poc7 after the pod is recreated. 
kubectl get pvc shows the claim remains Bound throughout, confirming PV/PVC lifecycle is independent of the pod lifecycle.


pv-pvc.yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: main-pv
spec:
  capacity:
    storage: 1Gi
  accessModes:
    - ReadWriteOnce
  storageClassName: common-storage
  persistentVolumeReclaimPolicy: Retain
  hostPath:
    path: /mnt/data/poc7
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: shared-pvc
spec:
  accessModes:
    - ReadWriteOnce
  storageClassName: common-storage
  resources:
    requests:
      storage: 1Gi
  volumeName: main-pv

POC 8 — Two Pods Sharing One PVC
Reuse (or create another) PVC.
Create pod-a and pod-b (both toolbox image), mounting the same PVC at /data.
pod-a: kubectl exec pod-a -- sh -c 'echo shared-data > /data/test.txt'
pod-b: kubectl exec pod-b -- cat /data/test.txt
Expected result: If both pods land on the same node and the PV is ReadWriteOnce, 
pod-b successfully reads shared-data — RWO restricts the volume to a single node, not a single pod, 
so co-located pods can share it. If the scheduler places pod-b on a different node, 
the mount fails or the pod stays stuck in ContainerCreating, since an RWO volume can't attach to two nodes at once. 
A ReadWriteMany PV (e.g. NFS-backed) would succeed regardless of node placement.

helm version
helm repo add csi-driver-nfs https://raw.githubusercontent.com/kubernetes-csi/csi-driver-nfs/master/charts
helm repo list
